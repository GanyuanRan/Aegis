# Aegis Public Repo Delocalization Checklist

状态：`Reviewed`

## 1. 文档定位

本文档定义 `Aegis Method Pack` 进入独立公开仓前的去本机化审计清单。

本文档回答以下问题：

1. 哪些内容属于本机化痕迹
2. 哪些位置当前最值得优先审计
3. 审计后应采取什么处理动作

本文档不负责：

- 代替 disposition 策略
- 直接声明所有内容已完成清理
- 把开发期证据全部从历史上抹掉

---

## 2. 去本机化对象定义

以下内容默认视为“需要审计”的本机化对象：

1. 本机绝对路径
   - 例如当前开发机上的 repo root 绝对路径
   - 例如当前开发机上的宿主工具 checkout 绝对路径
   - 例如当前开发机上的用户主目录绝对路径
2. 依赖当前私有环境的 runner 假设
3. 只适合本机排障的临时说明
4. 指向本地缓存、临时目录、私有工作目录的测试断言
5. 只对当前开发 lineage 有意义、但对公开用户没有价值的路径说明

## 4. 审计动作类型

每个命中项只允许进入以下五类处理之一：

1. `泛化`
   - 例如把本机绝对路径改成“repo root”或“current working directory”
2. `删除`
   - 如果该内容只服务本机排障、对公开用户无价值
3. `归档`
   - 如果内容有历史价值，但不应继续公开主叙事
4. `仅开发仓保留`
   - 如果该内容只适合当前开发仓而不适合公开发行主仓
5. `迁入 .local/`
   - 如果该内容仍需本地保留，但不应继续停留在公开候选路径

## 7. 修复轨

1. 真实根因
   - 当前开发仓中的部分文档与测试仍显式依赖本机路径和私有环境上下文
2. 唯一 canonical owner
   - 本文档
3. 最小必要改动
   - 不直接修改所有命中对象，先建立统一审计与处理规则
4. 兼容边界
   - 不删除对当前开发仍有证据价值的历史材料
5. 验证方式
   - 公开仓整理时逐项对照并记录处理结果

---

## 8. 退役轨

1. 旧对象在哪里
   - 零散存在于 current docs、历史材料与测试断言中
2. 是否仍在公开主链生效
   - 当前开发仓中仍可能被公开候选内容携带
3. 默认操作
   - 在 cutover 前统一审计并去本机化
4. 保留它们的唯一理由
   - 若仅为开发期证据或迁移历史，则应转 archive 或仅保留在开发仓
5. 验证
   - 公开仓版本中不再出现高显著度本机路径和私有环境假设

---

## 9. Architecture Review

执行去本机化审计时必须持续检查：

1. 是否误删了 current authority 所需的事实材料
2. 是否把开发期证据与公开用户文档混在一起
3. 是否把平台中立说明重新写成当前机器专属说明
4. 是否让公开仓的测试门禁依赖当前开发机目录结构
